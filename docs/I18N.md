# Translating Growsterr

English is the source. Every other language is a set of Python files that mirror the English ones key by key.
Anything a language doesn't have yet shows in English, or isn't served at all. Nothing crashes.

## The 41 languages

`en de nl fr it es pl ru uk ar sv da no ro az tr pt cs sk hu bg hr sl sr bs mk sq el fi et lv lt ga mt is ca eu gl lb cy be`

- **The list:** `apps/core/languages.py` holds the native names, `og:locale` values and flags.
- **URLs:** English lives at `/`, every other language under `/<code>/`.
- **Script:** `sr` is Serbian in Latin script. `ar` is right to left; the templates handle that, so you write nothing extra.

## The files of one language

| Create | Mirrors | What it holds |
|---|---|---|
| `apps/core/i18n/<code>.py` | `apps/core/i18n/en.py` | `CHROME`: header, menu, footer, WhatsApp button, 404 page (every page of the site)<br>`HOME`, `PRICING`, `HOW`, `ABOUT`: the core pages<br>`UPDATED`: the date the copy last changed |
| `apps/growth/i18n/<code>.py` | `apps/growth/i18n/en.py` | `UI` and `PLATFORM_UI["youtube"]`: the packages (also shown on home and pricing), the order page and the account area |
| `apps/pages/content/<code>/` | `apps/pages/content/en/` | The money pages: `ui.py` plus one file per platform. See `docs/CONTENT.md`, "Yeni dil eklemek" |

**Not translated:**

- **Legal pages:** `/terms/`, `/privacy/`, `/cookies/` and `/refunds/` stay English, because legal translations need a lawyer. Their header and footer still follow the visitor's language (`?lang=<code>`).
- **Emails and the 500 page:** these stay English as well.

## What turns a page on

- **`<code>.py` doesn't exist:** the chrome is English and there are no core pages in that language. `/<code>/pricing/` is a 404.
- **The file defines `CHROME`:** the header and footer speak the language on every page in that language, including the money pages, the order page and the account area.
- **The file defines a page dict:** that page is served, together with its hreflang, canonical, `<html lang>`, `og:locale` and language switcher.

| Page dict | URL it turns on |
|---|---|
| `HOME` | `/<code>/` |
| `PRICING` | `/<code>/pricing/` |
| `HOW` | `/<code>/how-it-works/` |
| `ABOUT` | `/<code>/about/` |

- **A key the file leaves out:** that key shows in English, and the check lists it. Don't ship a page dict half translated.
- **Restart after adding a page dict:** routes are built when the server starts, so restart it (a deploy does this).

## How to write `apps/core/i18n/<code>.py`

1. Copy `apps/core/i18n/en.py` to `apps/core/i18n/<code>.py`.
2. Replace the docstring with one line, e.g. `"""German copy of the core site (formal "Sie"). Mirrors en.py."""`.
3. Set `UPDATED = date(...)` to today. Change it whenever you change the copy; the sitemap's `lastmod` uses it.
4. Translate the values only. Keep the following exactly as they are:
   - **Names:** `CHROME`, `HOME`, `PRICING`, `HOW`, `ABOUT`, `UPDATED`.
   - **Keys:** every dict key, including the nested ones (`HOME["platforms"]["instagram"]`, `PRICING["rows"]["followers"]`, `HOW["flow"][0]["points"]`).
   - **Shapes:** a list or tuple keeps its length and order. Icons and photos are matched to items by position (`apps/core/content.py`). For example, `HOME["faqs"]` is 8 (question, answer) pairs, `PRICING["included"]` is 8 (title, text) cards and `HOW["flow"]` is 4 steps with 3 points each.
   - **Titles:** a title is a tuple `(before, highlighted, after)`, and the middle part gets the coral swoosh. Move words between the parts so the sentence reads naturally; any part may be `""`.
   - **Placeholders:** keep them exactly, never translated (see the next section).
   - **Brand and product names:** Growsterr, Sterr Agency, Sterr Technologies OÜ, Instagram, TikTok, YouTube, WhatsApp, Stripe, Apple Pay, Google Pay, Ekin Sipahi, and the package names Starter Creator, Rising Influencer and Pro Influencer.
5. Write `"Turkey"` and `"Tallinn, EU"` (`ABOUT`) in the language. The address stays as it is.
6. Run the check (see "Checking your work").

**Register:** use the same register as the language's `apps/growth/i18n/<code>.py` (e.g. German "Sie"), so the packages and the page around them match.

## Placeholders

Placeholders are filled in by the site. If one is missing the number disappears; if one is unknown it shows as written. The check catches both.

| Placeholder | Becomes | Where |
|---|---|---|
| `{price}` | The lowest monthly price, `$79.99` | `HOME["description"]`, `PRICING["description"]` |
| `{starter}` `{rising}` `{pro}` | Each package's typical monthly follower range, in the page's number format (`1.000–4.000` in German) | `HOME["faqs"]` |
| `{sister_brand}` `{legal_name}` `{registry_code}` `{address}` | Company facts from `apps/core/company.py` | `CHROME["company_line"]`, `ABOUT["rows"]` |

**Other files:**

- **The growth file:** it has its own placeholders (`{platform}`, `{audience}`, `{followers}`, `{likes}`, `{comments}`, `{price}`, `{email}`...). Keep every placeholder its English string has; `check_growth_ui` checks them.
- **The money pages:** see `docs/CONTENT.md`, "Yer tutucular".

## Copy rules

These apply in every language and every string, including alt texts and aria-labels.

- **Real people only:**
  - Never bots, never "instant".
  - "Instant" appears only to say that instant means bots and that we don't do it.
- **Packages only:** likes, views and comments are always part of a package, never sold on their own.
- **Numbers are typical monthly ranges, never promises:** say "typical", "usually".
- **Passwords:** we never ask for one, and the copy only ever says that we don't.
- **Never:**
  - "SEO", search engines, keywords or rankings.
  - "Guarantee", "free" or competitor names.
  - Crypto.
  - Verified or celebrity comments.
  - Gender targeting.
  - Reviews, ratings or statistics.
- **Voice:**
  - Write as the agency ("we"), never "I".
  - Wording about the founder stays gender-neutral.

The same rules in Turkish are in `docs/CONTENT.md`, "Metin kuralları". The check catches the forbidden words in English and in the languages `apps/pages/checks.py` knows. The rules about meaning, such as "instant" and nothing sold on its own, need a careful read.

## Checking your work

```bash
. .venv/bin/activate
python manage.py check_i18n <code>          # core + growth files of one language: what's missing, what's wrong
python manage.py check_i18n <code> --same   # also list strings still identical to English
python manage.py check_i18n                 # overview of all 41 languages
python manage.py check_growth_ui <code>     # the growth file alone, in detail
python manage.py check_pages --lang <code>  # the money pages
python manage.py test apps.core apps.growth
```

`check_i18n` reports each file of a language:

| Status | Meaning |
|---|---|
| `missing  HOME['faqs']` | That key shows in English |
| `missing  HOW (the whole section): /<code>/how-it-works/ isn't served` | The page dict is absent, so the page isn't served |
| `problem  ...` | Must be fixed: a different shape (English shows instead), a lost or unknown placeholder, an unknown key or name, a forbidden word, or `HOME`/`PRICING` without the growth file |

The last line for each language is `<code>: OK` when both files are complete and clean. It says `not finished` while a file is still missing, and `to fix` when there are problems. The command exits with 1 for `to fix`, and for any language named on the command line that isn't OK.

The tests fail on any *problem* in any language file (`test_every_translation_file_is_clean`). Missing keys don't fail the tests while a translation is in progress.

**Look at the result:** run `python manage.py runserver` (restart it after adding a page dict), then open these pages:

- `/<code>/`
- `/<code>/pricing/`
- `/<code>/how-it-works/`
- `/<code>/about/`
- `/order/?lang=<code>`
- `/terms/?lang=<code>`
